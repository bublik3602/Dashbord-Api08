# Внутренний веб-дашборд руководителя завода (Маслоэкстракционный комплекс)

Автономный промышленный веб-дашборд для руководителей подразделений. В реальном времени собирает и визуализирует ключевые показатели производства, логистики и энергоэффективности на едином экране.

---

## 1. Стек технологий и архитектура

* **Серверное окружение**: Hestia CP (Nginx/Apache, PHP 8+, MySQL/MariaDB). Автономное локальное размещение.
* **Backend**: Нативный чистый PHP (PDO) + SQL. Локальная база данных для аккумуляции и кэширования метрик.
* **Frontend**: HTML5, CSS3, JavaScript (ES6+), библиотека графиков [ApexCharts](https://apexcharts.com/), иконки Lucide. Современный светлый карточный интерфейс с крупной типографикой и цветовой индикацией отклонений.
* **Источники данных**:
  * **Zabbix API**: опрос датчиков весовой, счетчиков электроэнергии и воды, статусов узлов по расписанию (CRON).
  * **CRM (Электронная очередь)**: прямое SQL-подключение к базе данных CRM для мониторинга движения транспорта.
  * **Демо-режим**: система содержит встроенный генератор и демо-базу для мгновенного запуска и демонстрации.

## 2. Функциональные блоки

### Блок А: Производство и материальный баланс
* **Зона приёмки**:
  * Вход сырья на завод (семечка по автовесам, т) с контролем выполнения суточного плана.
  * Потери при подработке (усушка/сор) = $\text{Семечка на завод} - \text{Семечка в производство}$ (в тоннах и %).
* **Зона производства**:
  * Подача очищенного сырья в переработку (после сушилки/сепаратора, т).
  * Производственные потери = $\text{Сырье в производство} - (\text{Масло} + \text{Шрот} + \text{Лузга})$.
* **Выход готовой продукции**:
  * Интерактивная круговая диаграмма (Donut Chart) с распределением долей: **Масло сырое (~43.5%)**, **Шрот тостированный (~38.5%)**, **Лузга гранулированная (~16.9%)**, **Технологические потери (~1.1%)**.
* **Цветовая индикация отклонений**:
  * 🟢 **Зеленый** — потери в пределах нормы.
  * 🟡 **Желтый** — предупреждение (приближение к пороговому значению).
  * 🔴 **Красный** — превышение допустимой нормы потерь (с выводом Toast-оповещения).

### Блок Б: Логистика (Электронная очередь автотранспорта)
* Воронка движения транспорта из 4 ключевых этапов:
  $$\text{1. Записано} \longrightarrow \text{2. Заехало на завод} \longrightarrow \text{3. Взвешивается на автовесах} \longrightarrow \text{4. Выехало сегодня}$$
* Расчет среднего времени нахождения грузовика на заводе (целевой норматив: до 2 часов).
* Счетчик активного транспорта на территории.

### Блок В: Состояние узлов и энергоресурсы
* Текущая мощность ввода (кВт), накопленный расход электроэнергии за период (кВт*ч).
* Мгновенный расход технической воды (м³/ч) и суммарный объем за период (м³).
* Давление пара от котельной на лузге (бар).
* Удельный расход электроэнергии на тонну переработанного сырья (кВт*ч / т).
* Временной ряд (Area / Line Chart) с почасовой динамикой потребления энергии и воды.
* Индикаторы состояния ключевых узлов завода со светодиодной индикацией:
  * Сепаратор БИС-100 (Очистка)
  * Сушильный комплекс КЗС-50
  * Рушально-веечный агрегат РВО-2
  * Форпрессы МП-68 (Прессовый цех)
  * Экстрактор карусельный НД-1250 (Экстракция)
  * Паровой котел ДКВР-10 (Котельная)

## 4. Быстрый запуск на локальной машине через Docker

Если у вас установлен Docker:

```bash
docker compose up -d --build
```

После этого откройте браузер: [http://localhost:8080](http://localhost:8080).
База данных MariaDB поднимется автоматически и наполнится тестовыми данными из `database/schema.sql` и `database/seed_data.sql`.

## 5. Развертывание на боевом сервере Hestia CP

### Шаг 1. Клонирование репозитория
В панели Hestia CP создайте WEB-домен (например, `dash.factory.local`).
Подключитесь по SSH к серверу и перейдите в каталог домена:

```bash
cd /home/admin/web/dash.factory.local/public_html
git clone https://github.com/agasev-r/api08-free.git .
```

### Шаг 2. Создание базы данных в Hestia CP
1. В панели Hestia перейдите в раздел **DB** и создайте базу данных (например, `admin_dashboard`).
2. Создайте пользователя базы данных и задайте надежный пароль.
3. Импортируйте схему и демо-данные:

```bash
mysql -u admin_user -p admin_dashboard < database/schema.sql
mysql -u admin_user -p admin_dashboard < database/seed_data.sql
```

### Шаг 3. Настройка `config.php`
Скопируйте конфигурационный файл из шаблона:

```bash
cp config.sample.php config.php
nano config.php
```

Заполните параметры:
* Доступы к созданной базе данных `db`.
* URL и API Token для Zabbix (`zabbix`).
* Доступы к базе данных CRM (`crm_db`).
* Установите `'app_mode' => 'production'`.

### Шаг 4. Настройка заданий CRON в Hestia CP
В панели Hestia CP перейдите в раздел **CRON** и добавьте две задачи:

1. **Опрос датчиков и весов Zabbix** (каждые 5 минут):
   ```bash
   /usr/bin/php /home/admin/web/dash.factory.local/public_html/cron/sync_zabbix.php > /dev/null 2>&1
   ```
   *Расписание*: `*/5 * * * *`

2. **Синхронизация электронной очереди транспорта** (каждые 2 минуты):
   ```bash
   /usr/bin/php /home/admin/web/dash.factory.local/public_html/cron/sync_logistics.php > /dev/null 2>&1
   ```
   *Расписание*: `*/2 * * * *`

## 6. Настройка Git и автоматического деплоя (CI/CD)

1. Конфигурационные файлы `config.php` и `.env` добавлены в `.gitignore` и гарантированно не попадут в публичный репозиторий.
2. Для обновления боевого сервера достаточно выполнить:
   ```bash
   git pull origin main
   ```
3. При необходимости в Hestia CP можно настроить Webhook для автоматического выполнения `git pull` при пуше в ветку `main`.
